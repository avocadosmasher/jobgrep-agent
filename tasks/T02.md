# T02 · 골든 픽스처 세트

| | |
| --- | --- |
| Phase | P0 |
| 의존 | T01 |
| 소유 파일 | `fixtures/*.json`, `fixtures/README.md`, `tests/test_fixtures.py` |

## 맥락
이후 **모든 모듈이 상류 모듈 없이** 개발·테스트되게 하는 기반. 이게 부실하면 "수집기가 있어야 추출기를 만든다"로 태스크가 직렬로 묶여 전체 개발 방식이 무너진다.

## 할 일
아래 픽스처를 **실제 데이터**로 작성. JD는 실제 백엔드/AI인프라 채용공고 스타일로 현실감 있게 (요구역량이 충분히 다양해야 이후 테스트가 의미 있다).

| 파일 | 내용 |
| --- | --- |
| `jd_sample_backend.json` | `SourceDocument` 1건 — 백엔드 JD, 요구역량 12개 이상 |
| `jd_sample_aiinfra.json` | `SourceDocument` 1건 — AI 인프라 JD (GPU·서빙·분산학습 포함) |
| `competencies_required.json` | 위 JD에서 추출된 `CompetencyRecord[]` (정답 데이터) |
| `profile_sample.json` | `ProfileJSON` 1건 — D1~D5 고루 분포, **일부 축은 의도적으로 빈칸** |
| `criteria_sample.json` | `dict[comp_id, Criterion[]]` |
| `verdicts_all_met.json` | 집계 경계 테스트 — 전부 충족 |
| `verdicts_half.json` | 집계 경계 테스트 — 필수 절반 |
| `verdicts_mostly_unmet.json` | 집계 경계 테스트 — 대부분 미충족 |
| `brief_expected.json` | 위 입력으로 나와야 할 `StrategyBrief` 골격 (■ 필드만, ◇ 슬롯은 null) |
| `jd_injection.json` | T26용 — 본문에 지시문("이전 지시를 무시하고…")을 심은 JD |

`fixtures/README.md`에 각 파일의 용도와 어느 태스크가 쓰는지 표로 정리.

## 불변식
- 모든 픽스처가 해당 Pydantic 모델로 **검증 통과**해야 함
- `competencies_required.json`의 `name`은 JD 원문 표현 그대로 (일반화 금지)
- `evidence.quote`는 해당 JD 본문에 **실제 존재**하는 문자열

## 완료 조건
`tests/test_fixtures.py`가 모든 픽스처를 `Model.model_validate_json`으로 로딩 검증.

## 검증
```
pytest tests/test_fixtures.py -q
```
