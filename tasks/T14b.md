## 맥락 — 왜 이 카드가 신설됐나

T14가 `retrieve_candidates`를 만들었지만 **아무도 호출하지 않는다.** T14의 소유 파일은
`tools/retrieve.py`·`tests/test_retrieve.py` 둘뿐이라 노드 배선이 카드 범위 밖이었고,
T15는 렌더러라 이걸 붙이지 않는다. 경위는 DEVLOG D39·D40.

**파장은 "LLM 호출이 안 줄어든다"보다 넓다.** `my_level`이 전원 `None`이라
(`nodes/analysis_nodes.py`의 `aggregate`) 브리프의 계산 계층이 아래처럼 갉여 있다:

| 갉인 곳 | 원인 |
| --- | --- |
| **트랙2 우선순위가 사실상 무의미** | `level_gap()`에서 `mine`이 전원 `NO_LEVEL_INDEX` → 격차가 **JD 요구 레벨만** 반영하고 사용자 격차는 반영 안 됨 |
| `effort_band` 구간 왜곡 | `level_gap` 파생 |
| 트랙1 강점 정렬이 죽음 | `exceeds_requirement()`가 `my_level is None`이면 무조건 `False` |
| 카드의 "내 레벨 vs 요구"가 전부 "없음" | 렌더러 2종 공통 |

즉 현재 브리프는 **"이 JD가 뭘 요구하나"까지는 맞고 "나한테 뭐가 급한가"는 못 낸다.**
이 카드가 그 한 칸을 채운다. 제품의 핵심 주장이 여기 걸려 있다.

## 할 일

### 1. `retrieve` 노드 신설 (`nodes/analysis_nodes.py`)

```python
def retrieve(state: GraphState) -> dict:  # -> {"candidate_pairs": [...]}
```

- `state["required"]` × `state["profile"].competencies`를 `retrieve_candidates(...)`에 넘긴다
- `top_k=3` — 상태에 남는 후보쌍은 감사·후속 재사용(T23의 프리셋 축 매핑)용이다
- `profile`이 `None`이거나 `required`가 비면 **호출 없이** `{"candidate_pairs": []}`
- 부분 상태 갱신 dict만 반환 (저장소 고유 규약)

### 2. 그래프 배선 (`graphs/analysis_graph.py`)

`NODE_SEQUENCE`의 **`extract`와 `decompose` 사이**에 `("retrieve", retrieve)`를 넣는다.

여기인 이유 — 입력(`required`·`profile`)이 `extract` 직후 갖춰지고, 소비는 `aggregate`다.
그 사이 아무 데나 되지만 **입력이 준비되는 즉시**에 두면 나중에 `verify` 프롬프트를
후보쌍으로 좁히는 선택지가 열린 채로 남는다. 뒤에 두면 그 문이 닫힌다.

`interactive=True` 경로는 `node_sequence()`가 `INTERVIEW_AFTER` 기준으로 자동 계산하므로
**추가 작업이 없다.** 그 점을 테스트로 고정할 것.

### 3. 진행 표시 라벨 (`presets/node_labels.yaml`)

```yaml
  retrieve:
    label: 보유 역량과 후보 매칭
    counts:
      - key: candidate_pairs
        unit: 쌍
```

T13이 미배선 노드 라벨을 미리 넣어 뒀지만(`discover_jobs`·`collect` 등) `retrieve`는
없다. `app/progress.py`는 **손대지 않는다** — 라벨만 추가한다 (D34).

### 4. `my_level` 확정 (`nodes/analysis_nodes.py`의 `aggregate`)

**이 카드에서 유일하게 어려운 부분이다.** 규칙을 아래로 고정한다:

```
1. state == UNMET             → my_level = None
2. state == MET / ADJACENT    → 그 comp_id의 **첫 번째** 후보쌍이 가리키는
                                보유 역량의 level
3. 후보쌍 없음 / 그 보유 역량의 level이 None → my_level = None
```

**규칙 1이 핵심이다.** 임베딩 top-1은 "가장 가까운 것"이지 "대응하는 것"이 아니다.
보유 역량이 `Docker 사용`뿐인데 요구가 `Kubernetes 운영`이면 top-1은 Docker이고,
그 레벨을 그대로 찍으면 **없는 경력을 지어내는 것**이다(§7-3 위반). `retrieve_candidates`는
유사도 점수를 일부러 반환하지 않으므로(§7-2) 임계값으로 거를 수단이 없다.

그래서 **근거 기반 판정을 필터로 쓴다.** `aggregate_states`가 이미 근거 인용을 거쳐
`MET`/`ADJACENT`를 냈다는 것은 그 대응이 실제로 확인됐다는 뜻이다. 유사도가 아니라
**판정이 게이트다** — 이게 §7-2의 "유사도는 후보 추림에만"과 §7-3의 "지어내지 않기"를
동시에 지키는 유일한 조합이다.

규칙 2의 "첫 번째"는 `tools/retrieve.py`가 docstring으로 명문화한 순서
("같은 요구 역량 안에서는 유사도 내림차순")에 의존한다. **계약(`contracts/tools.py`)에는
그 문장이 없다** — 그러니 이 의존을 테스트로 직접 고정할 것(아래 검증 ④).

## 범위 밖 (건드리지 말 것)

- **`is_strength`는 채우지 않는다.** `BriefCard`에 해당 필드가 없어 화면·문서 어디에도
  나갈 경로가 없고, 필드 추가는 계약 변경(R1)이다. 이 카드는 R1을 밟지 않는다.
  단 `my_level`이 채워지면 `exceeds_requirement()`가 살아나 **트랙1 정렬이 강점
  우선으로 바뀐다** — §7-3의 실질적 일부는 이것만으로 선다.
- `verify` 프롬프트를 후보쌍으로 좁히는 것. 지금 규모(요구 26 × top-3 ∪ = 보유 8 거의
  전부)에선 실익이 없고, 호출 수는 배치라 애초에 안 준다. 문은 열어 두되 닫지도 열지도
  않는다.
- `contracts/**` — 수정 금지(R1).

## 불변식

- **노드는 `(GraphState) -> dict` 부분 갱신만 반환한다**
- **`aggregate`는 여전히 LLM을 부르지 않는다.** 후보쌍은 `retrieve` 노드가 이미 계산해
  상태에 넣어 뒀고 `aggregate`는 그걸 읽기만 한다 — 순수 규칙 함수라는 성질이 안 깨진다
- 임베딩 호출은 `llm/` 어댑터를 통해서만(R6) — `tools/retrieve.py`가 이미 그렇게 돼 있다.
  이 카드는 OpenAI SDK를 import 하지 않는다
- **`profile`이 없어도 그래프가 끝까지 돈다.** 후보쌍이 비고 `my_level`이 전원 `None`일 뿐,
  현재 동작(P0)과 완전히 같아야 한다

## 완료 조건

① `retrieve`가 그래프에 배선되고 `interactive` 양쪽 경로에 들어간다
② 픽스처 프로필로 돌리면 **최소 1건의 `MatchResult.my_level`이 `None`이 아니다**
③ `UNMET` 역량의 `my_level`은 **반드시** `None`이다
④ `profile=None`이면 예외 없이 현재와 같은 결과가 나온다

테스트가 깨질 수 있다. 깨지면 **테스트를 고치기 전에** 그게 회귀인지 기대값 변경인지
판단하고, 후자면 사유를 DEVLOG에 남길 것.

### 테스트에 반드시 넣을 것

- **뮤테이션 3종** (D35·D39와 같은 절차 — 일부러 깨서 그물을 확인한다)
  1. 규칙 1(`UNMET` → `None`)을 제거 → 실패해야 한다
  2. `retrieve`를 `NODE_SEQUENCE`에서 빼기 → 실패해야 한다
  3. 후보쌍에서 **첫 번째가 아니라 마지막**을 고르기 → 실패해야 한다 (순서 의존을
     고정하는 테스트가 실제로 있는지 확인하는 용도)

  D39에서 2건이 살아남았고 그중 1건은 실경로 no-op이라 온라인 테스트로도 안 잡혔다
