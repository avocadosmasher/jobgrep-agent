## 맥락
회사의 열린/과거 공고를 열거해 대분류·직무코드로 그룹핑하고 **사용자가 고르게** 한다.

**임의 선택·병합은 금지.** 모호성을 시스템이 삼키면 안 된다 — "백엔드 개발자" 공고가 3개인데 시스템이 하나를 골라버리면 사용자는 자기가 뭘 분석당했는지 모른다.

## 발견 경로 (우선순위)
```
① 사용자 입력 (붙여넣기/URL)  ← 백본. 이 경우 H1 자체를 건너뛴다
② 회사 채용페이지 탐색         ← 기본 증강
③ 공식 채용 API                ← 선택적 증강 (T20, 없어도 됨)
④ web_search                   ← 폴백
```

## 규칙
- 사용자가 이미 특정 공고 URL/본문을 준 경우 **이 체크포인트를 건너뛴다**
- **H1은 T12의 재개 루프를 그대로 재사용.** 새 HITL 메커니즘을 만들지 말 것
- 선택 결과는 `state["selected_job_ids"]`

## 완료 조건
공고 다건 상황에서 multiselect 선택 후 재개, 결과가 상태에 반영.
