# T15b · JD 이미지 업로드 → 텍스트 추출

| | |
| --- | --- |
| Phase | P2 (T15 뒤, Phase 3 앞) |
| 의존 | T15 |
| 소유 파일 | `llm/vision.py` (신설), `app/main.py` (수정 — 배선 공유 파일, §2-1), `tests/test_vision.py` (신설) |
| 읽어도 됨 | `contracts/**` (수정 없음 확인용), `llm/client.py` **시그니처만**, `llm/embeddings.py` (같은 패턴 참고) |

## 맥락

실사용 중 발견됐다: **JD 본문이 이미지로만 제공되는 채용 페이지가 있고, 그 이미지조차 다운로드가 막혀 있다.** 지금 입력 경로는 `text_area` 붙여넣기 하나뿐이라(`app/main.py:166-170`) 이 경우 사용자가 이미지를 보고 직접 타이핑해야 한다 — 사용성이 안 된다.

**다운로드 차단은 네트워크/DOM 계층 방어다.** 화면 캡처(스크린샷)는 렌더링된 픽셀을 그대로 뜨므로 그 방어를 신경 쓸 필요가 없다. 그래서 "다운로드를 뚫는" 대신 **"이미지를 입력으로 받는다"**로 문제를 바꾼다.

## 왜 새 OCR 엔진을 고르지 않나

T22(이력서 OCR)가 엔진을 미확정으로 남겨 둔 이유는 표·구획 같은 **레이아웃** 정확도가 필요해서다(설계도 §16 S7). JD는 구조 없는 본문 텍스트만 뽑으면 되므로 문턱이 낮다 — 이미 쓰고 있는 vision 지원 모델(`llm/client.py`의 `default_model()`)로 충분하다. **T22의 엔진 선정과 이 카드는 별개 결정이다.** 나중에 T22가 엔진을 고를 때 "JD도 같은 엔진으로 통일할지"만 한 번 재검토하면 된다(억지로 지금 합치지 않는다).

## 할 일

### 1. `llm/vision.py` (신설)

```python
def extract_text_from_image(image_bytes: bytes, mime_type: str) -> str
```

- `llm/embeddings.py`가 세운 전례를 따른다 — `llm/client.py`의 `_build_client`·`_ensure_env`를 **import해서 재사용**(복제 금지), 클라이언트 생성 방식이 바뀔 때 두 벌이 갈라지는 걸 막는다
- vision 지원 모델에 이미지를 실어 보내고 본문 텍스트만 반환한다 (구조화 출력 불필요 — 순수 텍스트 1개)
- `DEFAULT_INSTRUCTIONS`(인젝션 격리 문구, `llm/client.py:28-33`)를 그대로 적용한다 — JD 이미지 안에 지시문이 숨어 있을 가능성은 텍스트 JD와 동일하다
- 실패(`LLMError`) 시 예외를 전파한다 — 호출부(`app/main.py`)가 잡아서 폴백 안내로 바꾼다. 여기서 조용히 삼키지 않는다

### 2. 폼 확장 (`app/main.py`, `render_input_form()`)

`text_area` 옆에 이미지 업로드를 추가한다:

```python
jd_image = st.file_uploader("또는 JD 스크린샷 업로드", type=["png", "jpg", "jpeg"])
```

- 업로드되면 `extract_text_from_image()`를 호출해 **추출 결과를 `text_area`에 미리 채워 넣는다** (자동 제출 금지 — 사용자가 항상 검토·수정 가능한 상태로 둔다)
- 추출 실패 시 에러를 보여주고 기존 `text_area`로 폴백 — 부분 실패가 전체 실패가 되지 않는다 (T17·T06b와 같은 패턴)
- **`interrupt()`·`Command(resume=)`·`app/hitl.py`의 재개 루프는 쓰지 않는다.** 이 흐름은 그래프가 시작되기 전, 폼 제출 이전에 전부 끝난다 — 일반 Streamlit 위젯 상호작용일 뿐이다

## 불변식

- **`contracts/state.py`·`contracts/tools.py` 수정 없음.** 추출은 앱 레이어에서 끝나고 결과는 지금과 똑같이 `raw_jd_input`(순수 텍스트)으로 그래프에 들어간다 — 그래프는 이미지의 존재를 모른다
- **LLM 호출은 `llm/` 어댑터를 통해서만**(R6). `app/main.py`는 OpenAI SDK를 import하지 않는다
- **사용자가 항상 검토한다.** 추출 결과를 자동 신뢰하고 바로 분석을 돌리지 않는다 — 이 시스템의 "근거 없이 지어내지 않는다" 원칙을 입력 단계에도 적용한다
- 텍스트 붙여넣기 경로는 **그대로 둔다.** 이미지 업로드는 대안이지 대체가 아니다

## 완료 조건

이미지만 있고 텍스트가 없는 JD를 업로드했을 때, 편집 가능한 텍스트가 채워지고 그 상태로 분석까지 관통한다. 추출 실패 시나리오에서 앱이 죽지 않고 기존 붙여넣기로 폴백 가능하다.
